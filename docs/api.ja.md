# X16MXDRV API — 組み込み用リファレンス

[English](api.md)

X16MXDRV は X68000 の MXDRV 用 MDX(+PDX)を、ファイルのまま Commander X16 で鳴らすドライバです。
- FM:YM2151(OPM)と YM2164(OPP)に対応
- PCM:PCM8 互換で、VERA の PCM へ出力する
- 形式:RAM バンクに常駐し、ジャンプテーブル経由で呼び出す

ゲームなどに組み込めます。

> **注意:データが小さい代わりに、ドライバの処理は重い**
> - 曲データ(音符・音量・ソフトウェア LFO など)を再生しながらその場で解釈し、PCM は最大 8 音をソフトウェアで混ぜて VERA へ送ります。データは小さく済みますが、そのぶん再生中の CPU の負荷が大きくなります。
> - CPU 負荷の目安(8MHz、x16emu で計測。KERNAL の VSYNC 処理の約 2.5% を含む):FM だけの曲で約 10〜14%、PCM を使う曲で約 30〜50%。参考までに、FM だけの同じ曲を ZSM に変換して ZSMKit で鳴らすと約 4〜8% です。
> - PDX は読み込むときに X16 の上で展開するので、PCM の多い曲では 20 秒前後かかります。PC で作る P16 パック(4 章)なら数秒です。
> - RAM バンクを 4 本(ドライバ)使い、PCM を鳴らすには 1MB 以上の機種が要ります(1 章)。
> - ゲームで CPU の余裕が必要なら、PCM の音数を減らす(`setopt`)、FM だけの曲は ZSM で鳴らす、といった使い分けも検討してください。

## 1. 使う資源
| 資源 | 内容 | 備考 |
|---|---|---|
| RAM バンク 4 本 | `X16MXDRV.BIN`(25KB)。バンク D〜D+3 | D は任意。`$A000` にヘッダなしでロードする(KERNAL LOAD はそのまま次のバンクへ続けて書く)。4 本とも再生中に使うので、ほかのデータを置かない(D+3 のファイルの終わりより後も、ドライバの作業域) |
| ゼロページ | **専用 0 バイト** | `$02`〜`$1D`(KERNAL の r0〜r13)を、コアやローダーが動く間だけ借りる。割り込みのワーカーと API の入口でホストの値を保存し、出口で戻す。ホスト側での予約は不要 |
| golden RAM `$0400`〜`$07FF` | IRQ の入口、バンク間呼び出し、ミキサーの内側のループ | `init` で書き込む |
| 低位 RAM(ホストが指定) | PCM の音量表:512 バイト × スロット数(4〜16、推奨 8)、256 バイト境界 | PCM を使う場合のみ |
| RAM バンク(ホストが指定) | PCM のサンプル(展開後)。PCM パックを使う場合は、パックを読み込んだバンク | PCM を使う場合のみ。1MB 以上の機種 |
| MDX 用の RAM バンク | MDX ファイル。ホストがバンク M の `$A000` から読み込む。8KB を超えるファイルは M+1、M+2、… に続く(64KB で 8 本) | 再生中は保持しておくこと。65535 バイトまで(setmdx のサイズは 16 ビット) |
| VIA1 Timer 1 | 割り込み:PCM を使う曲は 2ms 周期、PCM なしの曲は tick に合わせた周期(下記) | 再生中のみ。停止すると元に戻る |
| IRQ ベクタ(CINV `$0314`) | 再生中に差し替える。元のハンドラには連鎖する | VERA の割り込み(VSYNC など)は元のハンドラで処理される |
| YM2151 | 全レジスタ | 再生中、ホストは YM を直接触らないこと |
| VERA PCM(FIFO・AUDIO_CTRL・AUDIO_RATE) | 曲が PCM を使う場合 | PSG は使わないので、ゲームの効果音に使える |

- 動作条件:8MHz を推奨。速度は `init` で測る
- CPU 負荷の目安(8MHz):FM のみの曲で約 10〜14%、PCM8 を 4 音使う曲で約 30〜50%。曲頭やループ点の重い tick の負荷は、先読み(下記)で吸収する
- 512KB の機種では PCM は使えない(`pcmmem` が C=1 を返す)。FM だけで再生できる

### 配置の例(mdxplay)

| メモリ | 用途 |
|---|---|
| バンク 1〜4 | `X16MXDRV.BIN`(D = 1) |
| バンク 5〜12 | MDX(8 本。65535 バイトまでのファイル) |
| バンク 13〜21 | `KANJI8.BIN`(プレイヤーのフォント) |
| バンク 22 | 一覧の曲のタイトル(プレイヤー) |
| バンク 23〜最後 | PCM のサンプルか PCM パック(`pcmmem 23, 最後`)。2MB なら 23〜255 |
| 低位 RAM 4KB(256 バイト境界) | PCM の音量表、8 スロット |
| golden RAM `$0400`〜`$07FF` | ドライバ |

## 2. 呼び出し方
API はバンク D を選んだ状態で `jsr`(`$A000` + n)で呼ぶ。いちばん簡単なのは KERNAL の `JSRFAR`(`$FF6E`)を使う方法で、A/X/Y/P がそのまま渡り、戻る。
- **prog8**:`%import x16mxdrv`(`driver/include/x16mxdrv.p8`)→ `mxdrv.init()` など
- **ca65**:`.include "x16mxdrv.inc"` → `MXDRV MX_INIT`(マクロが JSRFAR を展開する)
- **cc65**:`#include "x16mxdrv.h"` と `x16mxdrv_cc65.s` をリンクする → `mxdrv_init()` など。リンカ設定は標準の cx16 のままでよい
  - 注意:古い cc65 の `cx16.h` は、`RAM_BANK` を初期の試作機の番地(VIA1 のポート A)として定義している。現行機の RAM バンクのレジスタは `$0000`。同じ理由で、古い cc65 の `waitvsync()` は現行の ROM では戻らない(`demo/cc65demo.c` を参照)

`r0` = `$02`/`$03`(KERNAL の仮想レジスタ)。

| 番地 | 名前 | 入力 → 出力 |
|---|---|---|
| `$A000` | init | → A = YM チップ(1 YM2164 / 2 YM2151 / 0 不明)、X = CPU MHz、Y = OPM クロック(0 3.58MHz / 1 4MHz)。校正で約 0.4 秒かかり、その間は割り込みを止める |
| `$A003` | setmdx | A = バンク、X/Y = MDX ファイルの番地、r0 = サイズ → C=1 なら MDX ではない(タイトルの終わり `$0D $0A $1A` が先頭 1KB 以内にあり、PDX 名とその 0、オフセット表 34 バイトがすべて r0 バイトの中に収まること)。再生中なら先に止める。再生中に曲が書き込むのは、本文の中(リピートの回数)だけ |
| `$A006` | play | 先頭から再生する |
| `$A009` | stop | 停止して、YM と PCM を消音する |
| `$A00C` | fadeout | A = 速度(MXDRV の `$E7 $01` の値。0 なら 17)。最後まで下がると「終了」になる |
| `$A00F` | status | → A = bit0 再生中 / bit1 終了(最後の音まで出し終えた)/ bit2 フェード中 / bit3 PCM 有効 / bit4 シーケンス終了、X/Y = ループ回数(終了後は `$FFFF`) |
| `$A012` | title | → A = バンク、X/Y = タイトルの番地(Shift_JIS、`$0D` で終わる) |
| `$A015` | ticks | → X/Y = 進んだ tick 数 |
| `$A018` | setopt | A = 項目、X = 値(下表) |
| `$A01B` | pcmmem | A = 最初のサンプルバンク、X = 最後のサンプルバンク、Y = 音量表のページ、r0L = スロット数 → C=1 なら PCM は使えない |
| `$A01E` | pdxname | → A = バンク、X/Y = MDX 内の PDX 名の番地(0 で終わる)、C=1 なら PDX なし |
| `$A021` | pdxbegin | MDX を走査する → A = 読み込みが必要な (サンプル, レート) の組の数(0 = 不要)、C=1 なら PCM 不可 |
| `$A024` | pdxfeed | X/Y = PDX の続きを入れた低位 RAM のバッファ、r0 = 長さ → C=1 なら必要なデータがそろった(以降は読まなくてよい) |
| `$A027` | pdxend | → A = 入らなかった組の数、X = 読み込んだ組の数、Y = 1 なら曲が 96 組を超える(97 組目以降は読まない)。X>0 ならこの曲で PCM が有効になる |
| `$A02A` | pcmstat | → A = 発音中のボイス数、X/Y = FIFO のアンダーラン回数 |
| `$A02D` | snapshot | X/Y = 202 バイトのバッファ ← 表示用の状態(5 章) |
| `$A030` | pdxprog | → r0 = PDX の読み込み済みバイト数 / 256、r1 = 必要なデータの終わり / 256(PDX の目次を読むまでは 0) |
| `$A033` | pcmpack | A = PCM パック(`*.P16`)の見出しを読み込んだバンク B、r0 + r1L = 読んだサンプル部のバイト数(版 2 のみ。版 1 では見ない)→ A = 登録した組の数、X = 曲が必要なのにパックにない組の数(0〜96。`$FE` = 曲が 96 組を超えるので判定できない、`$FF` = 版 1 なので判定できない)、Y = 結果(4 章)、C=1 ならエラー(この曲の PCM は無効になる)。setmdx の後、pdxbegin〜pdxend の代わりに呼ぶ。ファイルの読み込みと合わせて、include の `loadpack` を使うのが簡単 |

### setopt の項目
| A | 内容 | 既定値 |
|---|---|---|
| 0 | YM チップの指定(1 YM2164 / 2 YM2151) | 自動判定 |
| 1 | 音程の補正(1/64 半音単位) | 3.58MHz なら 123、4MHz なら 0 |
| 2 | 1 回の割り込みで処理する tick の上限 K | 8 |
| 3 | PCM の同時発音数(1〜8) | 4 |
| 4 | PCM の遅延 L(× 4 サンプル) | 62(15.9ms) |
| 5 | ミュート(デバッグ用。1 で FM、2 で PCM) | 0 |
| 6 | 方式:0 直接 / 1 キュー(次の play から反映) | 1 |
| 7 | キュー方式の先読み A(× 4 サンプル) | 196(50ms) |
| 8 | PCM なしの曲で tick に合わせた割り込みを使う(1)/ 常に 2ms(0)。次の play から反映 | 1 |
| 9 | チャンネルミュート FM(bit n = FM の n 番。下記) | 0 |
| 10 | チャンネルミュート PCM(bit n = PCM の P+n 番) | 0 |

- **チャンネルミュート**(9 / 10):消したチャンネルも曲は普段どおり進み、YM と PCM への出力だけを止める。戻すと、そのチャンネルの音色・音程・音量のレジスタを書き戻し、伸びている音はその場から鳴る(PCM は次の音から)。マスクは曲を切り替えても保つ(`play` でも消えない)
  - 効くまでの時間:次の tick を処理するときに適用するので、最大で 1 tick + A + L(直接方式は 1 tick + L)
  - MXDRV のチャンネルマスク(出力の処理だけを飛ばす)とは違う。飛ばすと、発音の予約や LFO・ポルタメントの状態が、鳴っている場合とずれるため

- **キュー方式**:tick を A だけ先回りして処理し、FM の書き込みを L だけ遅らせて PCM とそろえる(ずれは 1ms 未満)。曲の演奏は、命令してから A + L ほど遅れて始まる。
- **直接方式**:FM は即時に書く。PCM は L だけ遅れる。重い tick(曲頭など)で PCM が途切れないよう、L は 40ms 程度が必要。

## 3. 手順
```
1. X16MXDRV.BIN をバンク D の $A000 にロードし、init
2. (PCM を使う場合)pcmmem で、サンプル用のバンクの範囲と音量表の領域を指定する(一度だけ)
3. MDX をバンク M の $A000 にロードし(次のバンクへ続く)、そのサイズで setmdx。
   読むのは、用意したバンクに収まるバイト数までにする。KERNAL LOAD はその終わりで止まらない
   (mdxplay は diskio.f_read で 8 本分まで読み、それより大きいファイルは断る)
4. (PCM を使う場合)次のどちらか
   a. PCM パック(4 章)を include の loadpack で読む。曲に足りない組がなければ使える    ← 速い
   b. pdxname で PDX 名を得て、PDX ファイルを開けたら pdxbegin → ファイルを先頭から pdxfeed
      (C=1 で打ち切ってよい)→ pdxend
5. play。status で終了やループ回数を見る。fadeout / stop
   - bit1(終了)は、キューに残った FM の書き込みと PCM のイベント、鳴っている PCM、FIFO の先行分 L まで出し終えてから立つ。bit4 はシーケンスが終わった時点で立つ(キュー方式では、出力より最大 A + L ほど先)
   - ループ回数も、シーケンスがループ点を通った時点で増える(キュー方式では出力より最大 A + L 先)
```
- **曲の切り替え**:3 からやり直す(setmdx が再生中の曲を止める)
- **ロード中の注意**:再生中に MDX のバンクやサンプルのバンクを上書きしないこと。別の曲のロードは stop してから行う

## 4. PCM パック(事前変換)
PDX の ADPCM を、ドライバと同じ計算で 8bit に展開しておいたファイル(`*.P16`)。PDX を X16 で展開するより、ずっと速く読める。展開した結果はビット単位で同じなので、どちらで鳴らしても PCM の出力は変わらない(`--x68filter` で作ったパックを除く)。

展開では、X68000 の出力と同じ 183Hz の 1 次のハイパスをかける(固定小数、各サンプルの頭で状態を 0 にする)。

| PCM の多い曲(PDX 225KB) | 読み込みにかかった時間 |
|---|---|
| PDX を展開(エミュレータの HostFS) | 18.4 秒 |
| PDX を展開(実機 OtterX、SD カード) | 21 秒 |
| パック(460KB)、エミュレータの HostFS / SD カードのイメージ | 1.1 秒 / 5.0 秒(KERNAL LOAD と同程度) |
| パック(460KB)、実機 OtterX、SD カード | 2.8 秒 |

実機の値は、RETURN を押してから音が鳴り始めるまでをストップウォッチで測ったもの(2026-11)。

### 4.1 作り方(`tools/mkpack.py`)
```
mkpack.py DIR [-r]                 フォルダの *.MDX を調べ、PDX ごとに 1 つの共有パック <PDX 名>.P16(版 2)
mkpack.py A.MDX B.MDX ...          その MDX 群の PDX ごとに共有パック
mkpack.py X.PDX [A.MDX ...]        PDX を指定(MDX がなければ、PDX の有効な全サンプルをレート 4 で)
mkpack.py SONG.MDX [PDX] [-o OUT]  1 曲用のパック <曲名>.P16(版 1、従来の形)
```
- **共有パック**(版 2):その PDX を使う曲が必要とする (サンプル, レート) の組の和を入れる。例:同じ PDX を使う 34 曲(PCM を使うのは 31 曲)で、共有パック 1 つが 150KB。曲ごとのパックなら 31 個で 2.9MB
- 名前:MDX の中の PDX 名から、パスを除き、大文字にし、`.` がなければ `.PDX` を足す。拡張子を `P16` に替えたものがパックの名前(`songs` → `SONGS.PDX` → `SONGS.P16`)。PDX は MDX と同じフォルダから探す
- オプション
  - `--all`:PDX の有効な全サンプルを、レート 4 で加える。後から足した曲がレート 4 だけを使うなら(パックにある組だけを使うなら)、作り直さずに済む。ほかのレートを使う曲を足したときは `--check` が不足を知らせるので、作り直す
  - `-r`:サブフォルダも、フォルダごとに処理する。`-d DIR`:出力先
  - `--check`:何も書かずに、パックが今の MDX と PDX に合っているかを調べる(足りない組、PDX の変更)
  - `--max-banks N`:サンプルのバンク数の上限(既定 232 = 2MB 機の mdxplay)
  - `--prune`:共有パックで置き換えた、曲ごとのパックを消す(その曲が何も失わない場合だけ)
  - `--x68filter`:X68000 のアナログの出力フィルタをかけたパックを作る(下の「実機風フィルタ」)。見出しのフラグの bit2 が立つ。`--check` と組み合わせると、フィルタ版のパックを調べる
- `--check` は、曲が必要とする組のサンプルの中身も、今の `mkpack.py` が作るものと比べる。古いツール(183Hz のハイパスより前)や、別のフィルタで作ったパックは、作り直しを求められる。収録の順番や余分な組は問わない
- **実機風フィルタ(`--x68filter`、numpy が要る)**
  - 数値の出典:Nano Drive 8(Fujix1 氏、https://github.com/Fujix1/NanoDrive8)で公開されている、X68000 の ADPCM の出力フィルタ。ハイパスは 183Hz の 1 次。ローパスは、X68000 CZ-600CE のコントロール回路図から導かれた 10 点の特性(−3dB は約 3.9kHz、15.625kHz で −32dB)
  - このプロジェクトでの当てはめ:ローパスを、2 次(3.8kHz、Q 0.78)× 1 次(7.3kHz)とした。公開された 10 点との差は 0.1dB 未満
  - かけ方:レートごとに、その特性を各サンプルのレートの半分まで近似する、因果的な最小位相の FIR(1024 タップ)を作り、線形畳み込みでかける。各サンプルの頭より前は 0
  - 制限
    - 各サンプルのレートの半分より上には効かない。サンプルをそのレートで鳴らすと、値の保持でその上に成分(像)が生じる。X68000 ではアナログのローパスがそれも削るが、このパックでは残る(15.6kHz を含むすべてのレート。例:3.125kHz の音の 12.5kHz の像で、約 25dB の差)
    - サンプルの長さは変えない。末尾の後のフィルタの余韻は切り捨てる
    - X16 が PDX から展開するものとは別の音になる。ドライバには X68000 のローパスはない
- 曲を足したら作り直す(フォルダを指定し直すだけ)。古いパックでも、足りない組は `pcmpack` の X で分かる
- 形式:4.4 節(`tools/mkpack.py` の先頭にも英語で書いてある)

### 4.2 読み込み(`loadpack`)
パックは見出しのバンク B(8192 バイト)と、B+1 以降のサンプル部 S バイトからなる。include の `loadpack` は次の手順で読み、`pcmpack` を呼ぶ。
1. 見出しのバンクを B に読み、版と大きさの整合を確かめる
2. B + バンク数が、使ってよい最後のバンクを超えるなら、読まずに拒否する
3. サンプル部を**ちょうど S バイトだけ**読む(MACPTR、1 回で最大 512 バイト)。ファイルが途中で終われば拒否する。S バイトの後にまだデータがあれば拒否する
4. `pcmpack(B)` に、読んだバイト数 S を渡す

| 言語 | 呼び方 |
|---|---|
| prog8 | `mxdrv.loadpack(name, bank, lastbank)` → `mxdrv.PK_*`。`mxdrv.pk_ver` / `pk_pairs` / `pk_missing`。`mxdrv.pdxnames()` で `mxdrv.pdxfile`(`SONGS.PDX`)と `mxdrv.packfile`(`SONGS.P16`) |
| cc65 | `mxdrv_loadpack(name, bank, lastbank)` → `MXPK_*`。`mxdrv_pkver` / `mxdrv_pkpairs` / `mxdrv_pkmissing`。論理ファイル 14(装置 8)を使う |
| ca65 | `driver/include/mxpkread.inc` を取り込み、ファイルを開いて `mxpk_read`(A = B、X = 最後のバンク)→ `mxpk_s` を r0 / r1L に入れて `MX_PCMPACK`。手順の例:`driver/include/x16mxdrv_cc65.s` の `_mxdrv_loadpack` |

結果(`pcmpack` の Y と同じ番号。読み込み側の拒否も同じ番号で返す)

| 値 | 名前 | 意味 |
|---|---|---|
| 0 | OK | 登録した。`pk_missing` が 0 なら、曲の必要な組はすべてある |
| 1 | NOTPACK | パックではない、または知らない版 |
| 2 | RANGE | 最後のバンクを超える(実 RAM を超える、`pcmmem` の範囲を超える場合も) |
| 3 | NOPCM | PCM が使えない(`pcmmem`) |
| 4 | LENGTH | ファイルが見出しの大きさより短い、または長い |
| 5 | BAD | 見出しや組の参照先が壊れている |
| 6 | NOFILE | 読めなかった(ファイルがない)。何も変えていない |

- エラーのときは(NOFILE を除き)、その曲の PCM は無効になる。B〜最後のバンクは書き換わっていることがある
- 足りない組があるとき(`pk_missing` が 1〜96 か `$FE`):鳴らせるが、その音は出ない。PDX があれば PDX を展開する方がよい
- 版 1 のパックでは、足りない組は判定できない(`$FF`)。曲名のパックなら、その曲用に作ったものとして使ってよい
- 装置は MACPTR に対応していること(SD カード、エミュレータの HostFS)
- **KERNAL LOAD で読まないこと**:LOAD はファイルの終わりまで書くので、長すぎるファイルは確保した範囲の後ろを壊す。中身を信用できるファイルに限るなら使えるが、版 2 は読んだバイト数(S = ファイルの大きさ − 8192)を r0 / r1L に入れて `pcmpack` を呼ぶ

### 4.3 候補の選び方(mdxplay)
mdxplay は、曲ごとに次の順で PCM を決める(`player/mdxplay.p8` の `load_pcm`)。ゲームなど、使うパックが決まっている場合は、`loadpack` の結果だけを見ればよい。
1. PDX 名のパック(`SONGS.P16`)、曲名のパック(`SONG.P16`)の順に読む。版 2 で足りない組がない、または版 1 で曲名のパックなら、それを使う
2. どちらも当たらなければ、PDX を展開する
3. PDX もなければ、最初に読めた「足りない組のあるパック」を使う(後で別のファイルを読んでいれば、読み直す)
4. どれもなければ FM だけで鳴らす

画面の「NOW PLAYING」には、PCM をどこから読んだか(`(P16 SONGS)`、`(PDX)`)を出し、足りない組などは最下行に出す。

### 4.4 形式
```
版 1(曲ごと)、バンク B:
   0  'MXPK'   4  版 = 1   5  組の数 n(96 まで)   6  サンプルのバンク数 nb   7  0
   8  n 組 × 9 バイト:sample lo, sample hi, rate, bank(相対。0 = B+1),
      addr lo, addr hi($A000〜$BF7F), length(ADPCM のバイト数、24 bit リトルエンディアン)
版 2(共有)、バンク B:
   0  'MXPK'   4  版 = 2   5  フラグ(bit0 共有、bit1 --all、bit2 --x68filter。読む側は見ない)   6  サンプルのバンク数 nb(1〜255)   7  0
   8  組の数 n(16 bit)   10  PDX の表の項目数 m(16 bit、最大 4096)
  12  サンプル部のバイト数 S(24 bit、ファイルの大きさ − 8192)   15  0
  16  PDX の大きさ(24 bit)   19  0   20  PDX の CRC32   24  PDX の名前(12 バイト、大文字、NUL 埋め)
  36  有効な項目の表:ceil(m / 8) バイト(bit i = PDX の i 番がデータを持つ)
      その後 n 組 × 9 バイト(版 1 と同じ並び)。(sample, rate) の順
バンク B+1 以降(版 1・2 共通):サンプルごとに後ろへ 0 を 64 バイト。各バンクはサンプル領域 8064 バイトと、
次のバンクの先頭 128 バイトの写し(最後のバンクにはない。最後のバンクは使った所まで)
```
- 版 2 の見出しの整合:36 + ceil(m / 8) + 9n ≤ 8192、(nb − 1) × 8192 < S ≤ (nb − 1) × 8192 + 8064
- 各組の参照先はパックの中にあること:相対バンク < nb、addr − $A000 < 8064、線形の位置 + 2 × 長さ + 64 ≤ S − (nb − 1) × 128
- サンプルのデータは、ドライバが PDX を展開した結果とビット単位で同じ。展開はサンプルごとに独立なので、同じ組ならどのパックでも同じバイト列になる
- 版 1 には S がない。読み込み側は組の表から求める:(nb − 1) × 8192 + (最後の組の線形の終わり − (nb − 1) × 8064)

## 5. snapshot の内容(202 バイト)
16 チャンネル分の配列(0〜7 FM、8〜15 PCM の P〜W)を 12 個並べ、その後に曲全体の値を置く。

| オフセット | 内容 |
|---|---|
| +0 / +16 | 音程の下位 / 上位(ノート × 64 + 5 + デチューン。`>> 6` でノート番号。0 = o0 C#) |
| +32 | フラグ(bit3 = キーオン中) |
| +48 | 音量(bit7 = 0 なら v0〜15、1 なら @v の生の減衰量) |
| +64 | パン(FM:bit6 L、bit7 R / PCM:bit0〜1 = 0 と 3 を入れ替えた値) |
| +80 | 音色番号(FM) |
| +96 | キーオン回数(値が変わればキーオンがあった) |
| +112 / +128 | デチューンの下位 / 上位 |
| +144 / +160 | ピッチ LFO / 音量 LFO の種類(0 = なし) |
| +176 | PCM のバンク |
| +192 | Timer-B |
| +193 | フェードの量 |
| +194 | フェード中 |
| +195 | 終了 |
| +196 | ループ回数(2 バイト) |
| +198 | tick 数(2 バイト) |
| +200 | 演奏中チャンネル(2 バイト、bit n = ch n) |

割り込み中にも更新されるので、厳密に同時点の値ではない。表示用。

## 7. 注意
- 再生中の割り込み:ドライバは T1 の割り込みの中で処理し、その間も割り込みを許可している。VERA の割り込み(VSYNC など)は、ドライバの処理中は次の T1 割り込み(2ms 以内。PCM なしの曲では 7.7ms 以内)で元のハンドラへ渡す
- PCM なしの曲(PDX がない、512KB 機など)では、T1 の周期を tick の周期の 1/k(k = 1, 2, 4, …、7.7ms 以下)にし、割り込みを tick に合わせる。割り込みの回数は毎秒 500 回から tick の回数の k 倍(多くの曲で毎秒 150〜200 回)に減る。テンポが変わると、その tick から T1 の周期を切り替えて合わせ直す
- ホストが自前の IRQ ハンドラを入れる場合:play の前に入れれば、ドライバがそれに連鎖する。play の後に CINV を差し替える場合は、元の値(ドライバ)に連鎖すること
- prog8 の `sys.waitvsync()` は `WAI` なので、ドライバの割り込みでも戻る。フレームを待つならジフィー(RDTIM)が変わるまで待つ(`player/mdxplay.p8` の `main.vsync`)
- 長時間の再生:内部の時刻は 24bit(約 18 分で一周)だが、差で比べているので問題ない
- 実機での確認状況(2026-11):OtterX(YM2151 互換の FPGA、3.58MHz)。YM2164 機は未確認
